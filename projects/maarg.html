maarg — Track Experiments with Zero Boilerplate.

A lightweight, local-first experiment tracking library that helps machine learning engineers capture experiment inputs, metrics, artifacts, execution time, and failures with minimal instrumentation — without requiring a tracking server.

View on GitHub ↗ Install from PyPI ↗

PROJECT OVERVIEW

Experiment tracking, without the overhead.

Machine learning experiments involve repeated runs, changing parameters, evaluation metrics, and generated artifacts. Tracking these consistently can introduce unnecessary boilerplate into the development workflow.

maarg was built to make that process simpler. With a lightweight Python decorator, it records experiment details locally, letting developers focus on building and evaluating models rather than manually logging every run.

Zero Boilerplate

Track experiments through a simple decorator, keeping instrumentation out of the main experiment logic.

Local-First

Store experiment runs in a local SQLite database without setting up a separate tracking server.

Run Comparison

Retrieve, filter, compare, and rank experiment runs to help evaluate different configurations.

TECHNICAL IMPLEMENTATION

A simple API backed by practical engineering.

maarg centers its workflow on a Python decorator. The tracking layer captures run information, while a SQLite storage backend keeps records available for later inspection and comparison.

INTERFACE

Python Decorator

The @track interface keeps the experiment function readable and reduces the need for manual logging calls.

STORAGE

SQLite Backend

Run records are stored locally in a SQLite database, with support for a configurable storage location.

ANALYSIS

Run Inspection

Query and filter recorded runs, compare configurations, and identify top-performing runs using available metrics.

example.py — illustrative usage 
from maarg import track


@track
def train_model(learning_rate=0.01, epochs=10):
    # Your model training code goes here.
    # Return or record the results as supported
    # by your experiment workflow.
    return {
        "learning_rate": learning_rate,
        "epochs": epochs,
    }


train_model(learning_rate=0.01, epochs=10)
train_model(learning_rate=0.001, epochs=20)

This example illustrates the decorator-first workflow. Confirm the exact usage against maarg's current public API before treating it as a tested example.

ENGINEERING APPROACH

Built around a deliberate design choice.

The central design decision was to keep experiment tracking lightweight. Instead of requiring users to configure a separate service or add logging statements throughout their code, maarg uses a decorator-based interface and local storage.

The project also emphasizes practical Python engineering: a focused public API, persistent run records, queryable experiment history, artifact handling, and tests for expected behavior.

maarg is an ongoing open-source project. Its direction is guided by keeping the developer experience simple while improving the reliability and usefulness of experiment tracking.
